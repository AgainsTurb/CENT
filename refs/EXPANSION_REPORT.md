## 4. Item 4 — the origin of HWD (the brief's conditional)

The brief said: find the original paper that introduced "Handwriting Distance" / HWD, and if the
origin cannot be established with confidence, say so and instead record that the paper will
attribute HWD to DiffBrush's usage. **The origin is established, so the fallback is not needed.**

**HWD was introduced by Pippi, Quattrini, Cascianelli and Cucchiara, "HWD: A Novel Evaluation
Score for Styled Handwritten Text Generation", BMVC 2023** (`hwd`, arXiv:2310.20316).

Four independent pieces of evidence, all retrieved:

1. **The paper's own abstract**, on the BMVC 2023 official proceedings page
   (`proceedings.bmvc2023.org/7/`): *"we devise the **Handwriting Distance (HWD)**, tailored for
   HTG evaluation."* The page's citation block gives the four authors, the title and BMVA 2023.
2. **arXiv** `id_list=2310.20316`: exact title, all four authors, `comment: Accepted at BMVC2023`.
3. **The authors' own code repository** `github.com/aimagelab/HWD` describes HWD as *"the primary
   evaluation score introduced in the paper."*
4. **An independent survey** (arXiv:2409.02683, *Rethinking HTG Evaluation*) calls it
   *"a newly introduced work [22]"* and cites exactly this paper.

Cross-check with the citing side: DiffBrush's retrieved arXiv HTML
(`arxiv.org/html/2508.03256v1`) lists this paper as reference **[45]** and writes *"We use the
**newly proposed** Handwriting Distance (HWD) [45]"* — consistent with 2023 being the origin, and
it describes HWD exactly as the HWD paper defines it (Euclidean distance between VGG16 features,
per writer, averaged). No earlier use of "Handwriting Distance" as a metric was found.

**Incidental finding worth passing on.** `docs/PROTOCOL_ALIGNMENT.md` §6 records two open
questions about HWD; the HWD paper answers the first:

- *"The exact VGG16 handwriting net behind HWD, and whether it is released."* — The backbone is a
  **VGG16 pretrained on Font2**, a synthetic text-image set built by rendering **10,400 English
  words in 10,400 calligraphic fonts** (100M+ samples, with paper-like backgrounds, geometric
  distortion and colour jitter), trained to classify calligraphic font; features come from the
  last convolutional block, images resized to height 32, whole image fed (no square crop), and
  HWD is the Euclidean distance between per-writer averaged feature vectors. The paper states
  the pretrained backbone *"will be released"*, and the repo provides the `HWDScore` implementation.
  **I did not verify that the weights are actually downloadable**, so HWD stays `NOT_RUN` on the
  same grounds as before until someone fetches them.

That is a protocol fact, not a bibliography fact; it is recorded here because it bears on whether
the HWD column can ever be filled, and because the paper's HWD section currently says the net is
unknown.

## 6. Why the title-match store was not re-resolved

`refs/verify_refs.py` re-resolves **every** candidate and writes `verified_refs.json`. Run
without `--resume` it can downgrade an existing `ACCEPTED` entry to `LOOKUP_FAILED` when a
registry throttles — and Crossref was throttling this IP with `HTTP 429` throughout this run
(DBLP was also unusable: it sits behind Anubis bot protection and returns an interstitial page
to plain HTTP). Re-running it would have risked the 44 entries the brief says to preserve, to
gain nothing: `make_bib.py` lets an override win over a store entry, so the bibliography is
identical either way.

What was run instead:

```
python refs/probe.py "Demystifying MMD GANs" "Improved Techniques for Training GANs" \
                     "Geometry Score: A Method For Comparing Generative Adversarial Networks"
```

`probe.py`'s Crossref branch returned no match for any of the three — as expected, because ICLR,
NeurIPS and PMLR proceedings **have no Crossref DOI**, so a Crossref title query can only return
unrelated journal articles whose titles happen to share words ("Enhancing GANs With MMD Neural
Architecture Search", "Improved Techniques for Training Single-Image GANs", …). Its arXiv branch
found `1801.01401` immediately and was rate-limited on the other two. That is exactly the failure
mode `refs/overrides.json` exists for, and the same route `fid`, `inkspire` and `dp_font` already
took: record the work from the record itself (arXiv `id_list`, PMLR/NeurIPS/BMVC proceedings
index, or a Crossref DOI fetched by DOI), with `evidence` naming what was read.

The nine records therefore live in `overrides.json`, and `make_bib.py` emits them from there.

## 9. Honest limitations

1. **`doi` is not typeset.** `IEEEtran.bst` does not print the `doi` field — the same is true of
   the existing 44 entries that carry DOIs (`hisac`, `diffwriter`, `dp_font`, `tgc_diff`). DOIs
   are recorded in `refs.bib` for auditability, not for the printed page. If CVPR's style should
   print them, that is a bibliography-style change, not an entry change.
2. **A pre-existing blemish, left alone.** `tgc_diff`'s note renders as *"iCDAR 2025 Best Paper"*
   for the same sentence-casing reason. It predates this work and the brief said to keep the 44
   intact, so it was not touched; bracing `ICDAR` in that one note would fix it.
3. **Crossref throttling.** Several DOI lookups initially returned `HTTP 429` and were retried
   later; all nine records were ultimately obtained from their registry or proceedings source.
   DBLP was not usable at all (Anubis interstitial), so it contributed nothing.
4. **`kid`'s venue** is confirmed by the arXiv record's comment field, not by OpenReview directly
   (403). One hop, stated rather than smoothed over.
5. **`csa_gan`'s year** is 2022 (volume year); DiffBrush cites 2021 (early access). Flagged, not
   silently chosen.
6. **HWD weights** — the HWD paper says the backbone will be released and the repo ships the
   scoring code; I did not verify that the weights are downloadable, so HWD remains `NOT_RUN` for
   the same reason as before.

## 10. Reproducing

```bash
python refs/make_bib.py            # regenerates refs/refs.bib from verified_refs.json + overrides.json
cp refs/refs.bib paper/refs.bib    # the pipeline's last step
```

To correct a field, edit `refs/overrides.json` and re-run both lines — never edit `refs.bib` by
hand, since `make_bib.py` overwrites it.
