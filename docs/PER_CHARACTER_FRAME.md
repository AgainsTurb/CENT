# CENT v4 design: per-character generation in a local frame

_Status: design only. Baseline to beat is `results/local_step6.png` — 8-line run with curve +
render losses, `err_mean 0.169`, `ooc 13/78`, 51.6 ms/step at batch 8 on an RTX 3080._

## Why this change

Measured across this session:

| quantity | result | verdict |
|---|---|---|
| stroke count | 78/78 exact | solved |
| placement (ooc) | 0–13 | solved on 1 line, drifts on 8 |
| stroke extent ratio | 0.965 | solved |
| curvature (param L1) | 0.105–0.169 | **not the binding constraint** |
| text conditioning | every line maps to the same attractor | **broken** |
| style conditioning | 50x weaker than text | **broken** |

The model is asked to learn, in one global token space, both *where* a character sits and *what
shape* its strokes have. Every patch that injected shape information (dictionary prototype) degraded
position, and every patch that injected position (anchors) left shape unchanged. They must be
separated structurally, not summed in one tensor.

## Contract

### Data (per character, local frame)

For line with characters `c_1..c_C`:

```
box_i  = (x, y, w, h)            # canvas units, from char_strokes + strokes
local_i = strokes in (0,1)^2     # origin = box top-left, divided by (w, h)
tokens_i = local Bezier tokens   # same 8-dim convention, dt_start relative to previous end
count_i  = number of strokes     # includes the trailing connector-strokes, as today
```

- `local_i` is **scale- and position-free**: every character occupies the unit square regardless of
  where it sits in the line.
- The connector strokes stay attached to the character they follow, so `local_i` still contains the
  pen's exit.
- No clipping: `local_i` coordinates may exceed `[0,1]` when a stroke overshoots its box, and the
  overshoot is preserved (measured: connectors routinely leave both neighbours' boxes).

### Model

```
M1  transcript encoder      text -> H                       (unchanged)
M2  style encoder           k refs -> z_g, z_l              (unchanged)
M3' anchor planner          H, z_g -> a_i = (x, y, w, h)    (supervised, unchanged)
M9  glyph generator         (char embedding[c_i], z_g, a_i size) -> local_i, count_i
M4  boundary planner        a_i, a_{i+1}, exit(local_i), z_g -> join_i, entry/exit anchors
```

- **M9 is a new module** and is where the character dictionary lives: an embedding per character
  (2,680 x 64) plus a small decoder over strokes. It sees **no absolute position** — hence it cannot
  fight the anchor head.
- Placement is a single, explicit transform: `global = a_i.xy + local_i * a_i.wh`. Applied once, at
  the end. Position and shape meet only here.
- Connectors are generated by M4 in **global** coordinates between two placed anchors, so the
  boundary contract `start(next) = exit_i + gap_i (1 - zeta_i)` stays as implemented.

### Losses

```
L = NLL_local(M9)                      # shape, position-free
  + count CE(M9)
  + anchor L1(M3')  + continuity(M3')
  + render L1 + coverage               # on the ASSEMBLED line, not on local glyphs
  + join/bridge (M4, s2 not just s3)
  + writer (aux)
```

The render loss must be computed **after assembly** — that is the whole point: it judges the line
the user sees, and it is the only term that can see a misplaced character.

## Acceptance tests, in order

1. **Local reconstruction** (unit test, no line assembly): for held-out characters, mean local-token
   error of M9 < 0.08 and `count` exact for >= 90 % of characters. This is measurable in minutes and
   does not involve placement at all.
2. **Two-row gate**: 8-line run, `ooc <= 5`, `err_mean < 0.15`, and **row 2 legible**. The picture
   remains the only acceptance criterion that has never been satisfied.
3. **Text swap**: same style refs, two transcripts. Outputs must differ in the right places
   (per-character local error to the correct glyph lower than to the other).
4. **Style swap**: same transcript, two writers. Distance between outputs non-trivial and each
   closer to its own writer's GT.

## Risks, stated up front

- **M9 needs character-level data — MEASURED, and we have it.** Corpus census (31,589 train
  lines, 817,631 character tokens, 2,660 distinct characters):

  | statistic | value |
  |---|---|
  | median occurrences per character | **83** |
  | characters with >= 5 occurrences | 2,617 / 2,660 |
  | characters with >= 20 occurrences | 2,480 |
  | characters with >= 50 occurrences | 1,686 |
  | token coverage at >= 5 / >= 20 / >= 50 | **100 % / 99.8 % / 96.6 %** |

  So a character dictionary is trainable **from this corpus alone**; the fallback to CASIA-HWDB
  character images or font-rendered prototypes is not required. This removes the main risk from the
  design and is the reason to build M9 next.
- **Assembly can hide errors.** If M9 is good and assembly is wrong, step 2 fails while step 1
  passes; the two tests are designed to distinguish exactly this.
- **The connector thesis is untouched** — M4 and the boundary contract survive unchanged, which is
  the reason to do this refactor rather than adopt OLHWG wholesale.

## What must NOT be carried over

- The additive character-prototype-on-`mu` experiment (steps 7a/7b): it degraded placement
  (`ooc 13 -> 82`) because it wrote into the same token the position head owned. It is committed as
  evidence and must not be reintroduced without the local frame.
- `lambda_layout = 0` runs: layout must stay supervised.
